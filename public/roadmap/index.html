FactoryFlow roadmap

A manufacturing operations intelligence platform: what is happening, why, what happens next, and which decisions could improve outcomes.

FactoryFlow currently runs on synthetic data from a deterministic simulation of a fictional control-panel manufacturer. The goal is a pilot with a real manufacturer once the milestones below are met. Order and scope may change.
Completed: foundation and reporting In progress: Phases 0–3 Planned: Phases 4–6
  1. Phase 0

    Architecture and contracts

    In progress

    Establish clear boundaries between simulation, analytics, and rendering, and define what every metric means.

    Built

    • Domain core with no UI or 3D dependencies
    • Seeded, replayable event history with validation
    • KPI dictionary and reporting layer
    • Test suite covering determinism and invariants

    Remaining

    • Remove placeholder files
    • Add contributor/agent guidance
    • Document implemented versus proposed features

    Done when: the path from data to every on-screen number is documented and the repository matches its docs.

  2. Phase 1

    Production routing realism

    In progress

    Replace one generic assembly timer with product-specific operations that draw on different resources.

    Built

    • Separate routings for NCP-100, NCP-200, and NCP-300
    • Quality inspection, rework, and machine downtime events

    Remaining

    • Full NCP-300 routing: kit, mount, wire, configure, test, disposition
    • Work centers distinct from physical workstations
    • Setup times and skill or equipment requirements

    Done when: different product mixes create observable, explainable bottlenecks, reproducibly.

  3. Phase 2

    Work-order and unit traceability

    In progress

    Reconstruct what happened to any order or individual unit, including failures and retests.

    Built

    • Work-order list and detail drawer with timeline, routing, and materials
    • Throughput chart in the Operations Explorer

    Remaining

    • Serialized manufactured units
    • Per-attempt operation history (first failure and retest)
    • BOM and routing revision captured on each work order
    • Link 3D selection to the same detail view

    Done when: selecting a unit shows its full manufacturing history without guessing.

  4. Phase 3

    Procurement and material constraints

    In progress

    Make material availability and supplier delays change what production can actually do.

    Built

    • Supplier purchase orders and receipts
    • Orders blocked by material shortage, with a KPI

    Remaining

    • Reservations distinct from consumption
    • Incoming quality hold and partial receipts
    • Shortage root cause and downstream impact

    Done when: a supplier delay visibly changes the executable schedule.

  5. Phase 4

    Workforce and finite-capacity scheduling

    Planned

    Model who can do the work and when, so capacity reflects people and skills, not only stations.

    Built

    • Nothing yet

    Remaining

    • Skill matrix, shifts, and absences
    • Workload versus capacity
    • Projected completion with stated assumptions

    Done when: adding a station does not raise throughput when skills are the limit, and the app explains why.

  6. Phase 5

    Scenario comparison

    Planned

    Compare proposed changes under the same demand and random seed without touching baseline data.

    Built

    • Nothing yet

    Remaining

    • Isolated baseline snapshots and what-if branches
    • Compare capacity, labor, defect rate, supply, and demand mix
    • Throughput, WIP, flow time, and on-time delivery side by side

    Done when: a manager can defensibly compare two changes.

  7. Phase 6

    Real-data readiness

    Planned

    Prove the same views work over a second, imperfect data source, as a step toward a manufacturer pilot.

    Built

    • Nothing yet

    Remaining

    • Second adapter from an external-style dataset
    • Source provenance, freshness, and capability states
    • Backend, authentication, and data-governance decisions, driven by the pilot

    Done when: the same screens run over two independent data sources without rewrites.

Status reflects a code audit on 2026-10-15. Phases are delivered as thin vertical slices; the next slice is the NCP-300 routing with a traceable work order.
