FactoryFlow/Roadmap

Roadmap

A manufacturing intelligence tool for investigating what is actually happening in a plant, why, and what it means for customer dates.

FactoryFlow runs on synthetic data from a deterministic simulation of a fictional control-panel manufacturer. It is an engineering reference implementation, not a production system. Order and scope may change.
Completed: foundation, 0.1.0 Public Preview Planned: 0.1.x, 0.2.0, 0.3.0
  1. Foundation

    Domain core, simulation and analytics

    Completed

    A deterministic, event-sourced model of a fictional control-panel plant, with every number traceable to events and state.

    Built

    • Domain core with no UI or 3D dependencies; seeded, replayable event history with validation
    • Separate routings per product, work centers distinct from stations, shifts, equipment pools, changeovers
    • Quality inspection, rework, machine downtime; supplier purchase orders, receipts and material-shortage blocking
    • Customer orders and shipments (dispatch)
    • KPI dictionary, contract tests on a canonical fixture, recorded performance baseline

    Remaining

    • Nothing for this stage

    Done when: the path from data to every on-screen number is documented and the repository matches its docs.

  2. 0.1.0

    Public Preview

    Completed

    Manufacturing intelligence on synthetic data that anyone can open and run: no login, no backend. Observed facts only, no forecasts.

    Built

    • Operations Explorer: work orders, work centers, bill of materials, inventory, throughput
    • Dispatch and order lead-time analytics: lateness, past-due unshipped orders, on-time in-full dispatch
    • Work-order time breakdown and indicative contributing conditions
    • Quality and scrap analytics; bottleneck “why” panel; material shortage impact
    • Order-to-work-order navigation, deep links, and 3D overlays linked to the Explorer
    • README and a plant manager guide
    • Apache-2.0 licence, dependency and asset review, screenshots, browser check of the Explorer and 3D links

    Remaining

    • Nothing for this release (tagged 2026-10-21)

    Done when: a visitor can follow a late order to its work orders, see where the time went, and find the work center in the 3D plant, in about two minutes.

  3. 0.1.x

    Investigation

    Planned

    Turn the dashboard into an investigation tool: surface what deserves attention, explain it with recorded evidence, and trace it to the records behind it.

    Built

    • Nothing yet

    Planned

    • Exceptions inbox: past-due orders, blocked work orders, queue build-ups, stations down, each with its evidence and threshold
    • Part delivery lead time, per part and per supplier: standard versus observed, reliability, open orders against their promised dates
    • Work-order ETA with material delay: material-ready time plus remaining work, labelled forecast (earliest feasible) with its inputs shown, so a part with a 2-day lead time adds 2 days to the estimate
    • Investigation trail (order → work order → work center → material → 3D) and comparison of two time windows

    Done when: a manager can go from a symptom to the records behind it, and every estimate shows what it is built from.

  4. 0.2.0

    Source Independence and Shipping

    Planned

    Show the analytics are not tied to the simulation, and extend the model past the dock door.

    Built

    • Nothing yet

    Planned

    • Shipment lifecycle: delivery events, carrier transit times, delivered-on-time and in-transit views, shipment timelines against the promised date (a schema change, shipped on its own)
    • The same app, unchanged, from a second independently structured data source, with provenance, validation and quarantine of bad records
    • Atomic reducer and a documented way to write a source adapter

    Done when: the same screens run over two independent data sources without changes to analytics, UI or 3D code.
